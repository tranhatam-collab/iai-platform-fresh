# IAI MASTER DOMAIN MISSION MAP
## Canonical role map for *.iai.one
## Version 1.0 (Locked)

---

## 0. PURPOSE

This document prevents role drift across all subdomains.

A domain may publish content.
It may not redefine the ecosystem.

This file is the canonical map for:
- surface role
- ownership
- allowed content
- forbidden content
- cross-team alignment

---

## 1. MASTER MISSION OF *.IAI.ONE

The mission of `*.iai.one` is to operate one coherent trust-rooted platform where:
- `iai.one` defines meaning and boundaries
- `home.iai.one` routes people into the right surface
- `app.iai.one` holds human-facing journeys
- `flow.iai.one` executes workflows, agents, and automation
- `dash.iai.one` controls runtime truth
- `docs` and `developer` make the platform teachable and extensible
- `cios`, `web`, and `pay` expand the market on the same trust and execution core

---

## 2. DOMAIN MISSIONS

### `iai.one`
Role: Constitutional root / trust root  
Does:
- define IAI
- define boundaries
- define system map
- route to main surfaces

Must never become:
- sales homepage
- feature landing page
- fundraising portal
- community feed

### `home.iai.one`
Role: Portal / entry point  
Does:
- route users by intent
- explain where to go next
- separate surfaces clearly

Must never become:
- second root
- product clone
- long-form manifesto

### `app.iai.one`
Role: User product surface  
Does:
- community
- lessons
- verification
- identity
- user-facing operations

Must never become:
- root charter
- deep enterprise admin
- docs mirror

### `flow.iai.one`
Role: Living execution surface  
Does:
- builder
- runtime
- node ecosystem
- templates
- execution onboarding

Must never become:
- generic automation marketing page
- community page
- docs clone

### `docs.iai.one`
Role: Knowledge and standards layer  
Does:
- explain concepts
- define architecture
- publish standards
- hold platform documentation

Must never become:
- blog farm
- sales site
- duplicate product landing

### `developer.iai.one`
Role: Build layer  
Does:
- API references
- SDK directions
- auth/session docs
- integration guides
- runtime contracts

Must never become:
- general public marketing page
- philosophical essay surface

### `dash.iai.one`
Role: Living control system / operations  
Does:
- runtime truth
- actions
- approvals
- proofs
- logs
- system health
- billing and operational control

Must never become:
- chart-only dashboard
- public marketing surface
- fake preview shell

### `api.iai.one`
Role: Backend authority  
Does:
- browser-facing backend
- trusted core authority
- canonical backend endpoints for shared product functions

Must never become:
- public copy layer
- random endpoint dump

### `api.flow.iai.one`
Role: Flow execution authority  
Does:
- flows
- runs
- nodes
- agents
- billing events
- runtime control

Must never become:
- shadow duplicate API with conflicting logic

### `nft.iai.one`
Role: Public trust layer  
Does:
- registry
- disclosure
- proof model
- issuance and verification-facing public trust surface

Must never become:
- speculative marketplace
- hype NFT product

### `cios.iai.one`
Role: Enterprise intelligence product  
Does:
- enterprise onboarding
- demos
- B2B use cases
- customer intelligence positioning

Must never become:
- root identity layer
- consumer product surface

### `web.iai.one`
Role: Website creation and commerce growth layer  
Does:
- free informational sites
- paid business and commerce sites
- templates
- AI-assisted website generation
- Flow-powered lead and business automation

Must never become:
- generic template gallery without platform integration
- second root brand

### `pay.iai.one`
Role: Payment and settlement layer  
Does:
- checkout
- invoices
- payment flows
- transaction coordination
- merchant/payment authority functions

Must never become:
- consumer wallet brand without trust boundaries
- separate fintech brand detached from IAI core

### `noos.iai.one`
Role: Future aggregate / meaning layer  
Does:
- future aggregate intelligence and meaning layer only when core products are alive

Must never become:
- fundraising detour
- random future-tech page
- replacement for Dash

### `mail.iai.one`
Role: Internal infrastructure only  
### `cdn.iai.one`
Role: Internal infrastructure only  
### `flows.iai.one`
Role: Internal automation only

These must never be marketed as flagship surfaces.

## 4. HARD RULES

- No surface may redefine IAI
- No surface may change its role without root approval
- No team may publish contradictory mission language
- All public surfaces must follow the Language Codex and UI Text System
- Billing, auth, proof, and trust language must remain shared
