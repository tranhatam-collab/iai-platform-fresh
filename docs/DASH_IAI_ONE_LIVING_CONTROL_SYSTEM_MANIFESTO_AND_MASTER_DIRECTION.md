## 0. Why This File Exists

IAI Flow is no longer to be understood as:
- a drag-and-drop workflow tool
- a better automation builder
- a more advanced orchestration UI

IAI Flow is being repositioned as a living orchestration system:
- action
- memory
- intelligence
- control
- proof
- evolution

If Flow changes at that level, Dash must also change.

Because:
- Flow may become the living execution fabric
- Dash is where humans experience, govern, and shape that fabric

Without this shift, Dash remains:
- a runtime dashboard
- an operator panel
- a control UI

That is not enough.

---

## 1. Absolute Definition

IAI Dash is not:
- a metrics dashboard
- an admin panel
- a logs viewer
- a prettier operator console

IAI Dash is:

The Living Control System of IAI.

It is the human-facing layer where:
- the state of life is seen
- the state of work is understood
- the state of execution is governed
- the state of intelligence is reviewed
- the next action becomes visible
- the system becomes steerable

Flow executes.
Dash gives living control.

## 5. The Five Layers Of Dash

### Layer 1 - Life Layer

Dash must always answer:
- What state is this person in?
- What state is this team in?
- What state is this system in?

Minimum outputs:
- Clarity
- Stability
- Value
- Legacy

These are not vanity scores.
These are living operating signals.

### Layer 2 - Execution Layer

Dash must show:
- what is running
- what failed
- what is blocked
- what is waiting
- what is drifting

It must not simply list runs.
It must reveal operating pressure.

### Layer 3 - Agent Layer

Dash must expose AI activity as a governable layer.

Users must be able to see:
- which agent is active
- what role it is playing
- what it is suggesting
- what it is waiting for
- what it has already done

Agents must never remain invisible.

### Layer 4 - Proof Layer

Dash must make reality verifiable.

Every meaningful action should be linkable to:
- proof
- source
- time
- decision path
- verification state

Dash is where trust becomes practical.

### Layer 5 - Decision Layer

Dash must answer:
- What matters now?
- What should happen next?
- What requires approval?
- What is most likely to improve the system?
- What is creating hidden damage?

Without this layer, Dash is only observation.
With this layer, Dash becomes control.

## 10. The Next-Best-Action Model

Every meaningful screen in Dash must be able to produce:
- the most urgent action
- the most valuable action
- the most stabilizing action
- the safest action

At minimum, Dash should be able to compute:
- if user stability is dropping -> protect rhythm
- if work value is low -> clarify output
- if execution backlog is growing -> reduce load or prioritize
- if proofs are missing -> verify trust layer
- if approval is pending -> surface the bottleneck

This is not AI chat.
This is operating intelligence.

## 11. Memory As A First-Class Dash Layer

Dash must not only show current state.
It must remember:
- recent patterns
- repeated failures
- repeated bottlenecks
- action completion history
- risk recurrence
- proof lineage
- decision history

This memory should shape the next state of the dashboard.

Dash without memory becomes reactive.
Dash with memory becomes adaptive.
